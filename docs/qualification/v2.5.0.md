# IoT-MD v2.5.0 release qualification

## Release identity

- Version: `2.5.0`
- Release sequence: `2705`
- Source commit: `7eca6ef36f24cb484a901fb461a8ec1bc2e51d07`
- MicroPython: `1.29.0` at `0fd6c573ea815774668bbb16b8e197c8822368b2`
- ESP-IDF: `5.5.1` at `fcae32885b0296b32044cb99ecbdc50d98dddb83`
- Board/variant: `IOTMD_ESP32_S3` / `SPIRAM_OCT`

## Verification evidence

- The complete host suite passed: 486 tests.
- Architecture dependency and frozen recovery-import closure checks passed.
- The production core was built with Secure Boot v2, flash encryption,
  encrypted NVS, the native cryptography module and the frozen recovery
  manifest enabled.
- The signed OTA image is 1,511,424 bytes, 72.1% of the 2 MiB application
  partition and below both repository size gates.
- Application, core and firmware-first universal manifests, signatures,
  component hashes, release sequence and embedded source revision were
  independently verified before publication.
- The final beta.5 portal and upgrade behavior was confirmed on an ESP32-S3
  device before the same tested source was promoted to stable v2.5.0.

## Qualified limitations

- Wi-Fi remains the required production network and recovery interface.
- ESP32-S3 USB device and NCM hardware capability are reported separately,
  but production USB NCM integration is unavailable and the `usb_ncm` feature
  remains disabled.
- TLS session handles are an architectural seam only; MicroPython 1.29 does
  not expose a stable session-resumption API, so every outbound TLS connection
  performs a full handshake.
- ESP-IDF 6 is outside this release baseline and requires a separately
  qualified future MicroPython alpha.
