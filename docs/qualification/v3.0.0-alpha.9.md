# IoT-MD v3.0.0-alpha.9 qualification

Status: **awaiting hardware and interoperability evidence**.

The host suite and production-secure ESP32-S3 compile establish that:

- platform ABI 5 and configuration contract version 4 agree;
- GPIO, ADC, UART, I2C and SPI constructors are linked into the native module;
- only I2C/SPI claims can be shared and their effective configuration is
  compared before native instance reuse;
- owner/soft-restart cleanup, GPIO interrupt removal and peripheral recovery
  are bounded;
- production Wi-Fi, MQTT, listener and syslog lifecycle adapters satisfy the v3
  transport contracts;
- installed identity records expose stable opaque handles rather than paths;
  and
- stale trust-removal generations fail closed.

Still required on physical hardware:

- all 13 declared module variants across each native physical backend;
- exclusive conflicts and compatible/incompatible shared-bus combinations;
- interrupt delivery, cleanup, queue saturation and soft-restart cleanup;
- driver failure and peripheral reconstruction;
- Wi-Fi reconnect plus MQTT/Home Assistant, HTTPS portal, mTLS Device API and
  syslog shadow parity under network faults;
- every supported enrollment method, renewal, trust replacement/removal and
  certificate-failure recovery; and
- confirmation that support, portal and API projections never expose internal
  credential locators or private material.

These results do not qualify native paired trial/rollback or bare-ESP-IDF
recovery. Active-v3 cutover remains blocked.
