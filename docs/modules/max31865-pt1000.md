# MAX31865 PT1000

## Hardware and configuration

Use `class: sensor` and `subclass: MAX31865-PT1000`. Configure the `max31865`
object with `spi`, `sck`, `mosi`, `miso`, `cs`, `baudrate`, `wires` (2 or 3),
`filter_hz`, `rtd_nominal`, `ref_resistor`, and `precision`. Configure all bus
pins explicitly on the production ESP32-S3 board. The supported standalone
example uses SPI 1 on SCK GPIO 12, MOSI GPIO 11 and MISO GPIO 13 with CS GPIO
10; the HTW example uses the same bus with CS GPIO 10 and GPIO 9. The driver's
legacy SPI 0 GPIO 2/3/4 and CS 5 fallbacks are retained for old configurations,
but GPIO 3 is a boot-strapping pin and those defaults are not the recommended
N8R8 wiring. The electrical defaults are a 1 MHz bus, PT1000 and a 4.3 kΩ
reference. `pollinterval` defaults to 30 seconds.

The driver publishes temperature plus resistance, raw RTD and MAX31865 fault
diagnostics. Multiple devices may share one identically configured SPI bus but
must use distinct CS pins. See the
[single-sensor example](../../examples/module_settings.max31865_pt1000.example.json)
and [shared-bus example](../../examples/module_settings.dual_pt1000_voltage_display.example.json).

## State and diagnostics

The state payload contains configured keys such as temperature, resistance,
raw RTD and fault. MQTT, the API and optional HA discovery use the same values.
The module is read-only. A non-zero MAX31865 fault should be investigated before
using the temperature; common causes are open/short sensor wiring, incorrect
2/3-wire selection, reference-resistor mismatch, supply/grounding problems or a
conflicting CS pin. Select 50 or 60 Hz filtering for the local mains frequency.

Temperature accuracy depends on the probe class, lead arrangement, reference
resistor and installation. It is not automatically a safety-rated measurement.
